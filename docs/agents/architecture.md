# Architecture Patterns

Key architecture patterns for this project.

## Event-Driven Bridge

Communication between the Go service and the React frontend:

- **Go → React**: `app.EventEmit("event-name", data)` → `listen("event-name", handler)` (Wails runtime events, wrapped by `src/lib/shell/events.ts`)
- **React → Go**: Use typed commands from `@/lib/app-bindings`

## Typed commands (wails3 bindings)

Always use the typed commands, never raw runtime calls:

```typescript
import { commands } from '@/lib/app-bindings'
const result = await commands.loadPreferences() // ✅ Type-safe
```

After adding or modifying Go commands, regenerate the bindings
(the generated files are gitignored — the frontend build fails without them):

```bash
cd wails && wails3 generate bindings -clean=true -ts -i
```

## i18n

```typescript
import { useTranslation } from 'react-i18next'
const { t } = useTranslation()
return <h1>{t('myFeature.title')}</h1>
```

- Translations live in `/locales/*.json`
- Use CSS logical properties for RTL support

## File Organization

```
src/
├── components/          # React components by feature
│   ├── ui/              # shadcn/ui components (don't modify)
│   └── layout/          # Layout components
├── hooks/               # Custom React hooks (use-*.ts)
├── lib/
│   ├── commands/        # Command system
│   ├── bindings.ts      # Auto-generated by wails3 (don't edit)
│   └── app-bindings.ts  # Typed facade re-exported from bindings.ts
├── store/               # Zustand stores (*-store.ts)
└── services/            # TanStack Query + Go service integration
wails/                   # Go shell (internal/service, internal/app, cmd/dg)
locales/                 # i18n translation files
docs/developer/          # Architecture documentation
docs/agents/             # Agent coding guidelines (this directory)
```
